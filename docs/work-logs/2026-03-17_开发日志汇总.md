### 内置工具（`src/tools/builtins/`）

#### EditFileTool（`edit_file.py` ~81 行）

通过搜索替换模式精准编辑文件。

| 参数 | 必填 | 说明 |
|------|------|------|
| `path` | ✅ | 文件绝对路径 |
| `old_string` | ✅ | 要被替换的原始文本（精确匹配） |
| `new_string` | ✅ | 替换后的新文本 |
| `expected_replacements` | ❌ | 预期替换次数，默认 1 |

- 严格校验 `old_string` 在文件中的匹配次数是否等于 `expected_replacements`
- 匹配次数不符时直接报错，不执行替换
- 文件不存在时返回错误

#### MultiEditTool（`multi_edit.py` ~106 行）

对同一文件按顺序执行多次搜索替换，具有原子性。

| 参数 | 必填 | 说明 |
|------|------|------|
| `path` | ✅ | 文件绝对路径 |
| `edits` | ✅ | 编辑操作数组 |
| `edits[].old_string` | ✅ | 要被替换的原始文本 |
| `edits[].new_string` | ✅ | 替换后的新文本 |
| `edits[].expected_replacements` | ❌ | 预期替换次数，默认 1 |

- **原子性**：所有编辑在内存中依次应用，任一失败则整体不写回
- **创建新文件**：文件不存在时，若首个编辑的 `old_string` 为空则创建文件
- **追加内容**：`old_string` 为空时直接追加 `new_string` 到内容末尾
- 编辑按顺序应用，后续编辑基于前一编辑的结果

#### ReadFileTool（`read_file.py` ~110 行）

读取本地文件内容，支持行范围。

| 参数 | 必填 | 说明 |
|------|------|------|
| `path` | ✅ | 文件绝对路径 |
| `offset` | ❌ | 起始行号（从 1 开始） |
| `limit` | ❌ | 读取行数 |

- 输出 `cat -n` 格式（带行号）
- 单行最长 2000 字符，超出截断
- 输出超过 60000 字符时截断（总输出字符上限）

#### WriteFileTool（`write_file.py` ~53 行）

创建或覆盖写入文件。

| 参数 | 必填 | 说明 |
|------|------|------|
| `path` | ✅ | 文件绝对路径 |
| `content` | ✅ | 写入内容 |

- 父目录不存在时自动创建
- 返回写入字符数

#### LsTool（`ls.py` ~94 行）

列出给定路径中的文件和目录。

| 参数 | 必填 | 说明 |
|------|------|------|
| `path` | ✅ | 要列出内容的目录绝对路径 |
| `ignore` | ❌ | glob 模式数组，用于忽略匹配的文件/目录 |

- 条目按 **目录在前、文件在后** 排序，同类按名称字母序排列
- 目录显示为 `[目录] name/`，文件显示为 `[文件] name (大小)`
- 文件大小自动格式化为 B / KB / MB / GB / TB
- 使用 `wcmatch.fnmatch` 匹配 ignore 中的 glob 模式，支持 `{}` 花括号展开
- 路径不存在、不是目录、权限不足时返回错误

#### GlobTool（`glob.py` ~89 行）

快速文件模式匹配工具，适用于任意规模的代码库。

| 参数 | 必填 | 说明 |
|------|------|------|
| `pattern` | ✅ | glob 模式，例如 `**/*.py` 或 `src/**/*.ts` |
| `path` | ✅ | 搜索的起始目录绝对路径 |

- 使用 `wcmatch.glob` 进行模式匹配，支持 `**` 递归和 `{}` 花括号展开，只保留文件（过滤目录）
- 结果按修改时间降序排序
- 输出相对于搜索根目录的路径
- 捕获无效 glob 模式异常
- 路径不存在或不是目录时返回错误
- 没有匹配结果时返回友好提示

#### GrepTool（`grep.py` ~141 行）

快速内容搜索工具，在文件中搜索匹配正则表达式的行。

| 参数 | 必填 | 说明 |
|------|------|------|
| `pattern` | ✅ | 正则表达式模式（Python re 语法），例如 `def\s+main`、`import.*os` |
| `path` | ✅ | 搜索的起始目录绝对路径，会递归搜索所有子目录 |
| `include` | ❌ | 按文件名模式过滤，例如 `*.py`、`*.{js,ts}`。不指定则搜索所有文件 |

- 输出格式为 `文件路径:行号:匹配内容`
- 使用 `Path.rglob()` 递归遍历文件，结合 `re` 模块逐行匹配，使用 `wcmatch.fnmatch` 进行 include 过滤（支持 `{}` 花括号展开）
- 文件按修改时间降序排序
- 最多返回 200 条结果（`MAX_RESULTS`），超出时截断并提示
- 捕获无效正则表达式的 `re.error` 异常
- 路径不存在或不是目录时返回错误
- 没有匹配结果时返回友好提示

#### BashTool（`bash.py` ~130 行）

在持久 shell 会话中执行命令。

| 参数 | 必填 | 说明 |
|------|------|------|
| `command` | ✅ | 要执行的 shell 命令 |
| `timeout` | ❌ | 超时秒数，默认 120，最大 600 |

- **持久会话**：通过实例变量 `_process` 维护同一个 `/bin/bash` 子进程，上下文（环境变量、历史等）跨调用共享
- **sentinel 机制**：用随机标记 + `$?` 获取退出码，精确区分命令输出边界
- 输出超过 30000 字符时截断（保留首尾）
- 超时后自动 kill 进程并重置会话

#### BackgroundBashTool（`bash_background.py` ~252 行）

后台运行长时间命令，异步执行不阻塞对话。

| 参数 | 必填 | 说明 |
|------|------|------|
| `action` | ✅ | 操作类型：`start` / `status` / `stop` / `list` |
| `command` | ❌ | 要执行的命令（action=start 时必填） |
| `job_id` | ❌ | 任务 ID（action=status/stop 时必填） |
| `tail` | ❌ | status 时返回最近多少行输出（默认 50，最大 1000） |

- **异步执行**：命令在后台异步运行，启动后等待 1 秒获取初始输出即返回
- **缓冲区管理**：后台 reader 协程持续读取进程输出到缓冲区，最大 3000 行，超过时截断
- **并发限制**：最多同时运行 5 个后台任务
- **终止逻辑**：terminate 后等待 5 秒，超时则 kill
- **状态模型**：内部使用 `_BackgroundJob`（Pydantic BaseModel）维护任务状态
- **类变量**：`_jobs` 和 `_tasks` 为 `ClassVar`，确保同一实例共享任务状态
- **上下文注入**：重写 `context_injection()` 返回活跃任务摘要，供 system prompt 注入
- **资源清理**：重写 `cleanup()` 终止所有后台进程并清理 task

### 工具注册

`BUILTIN_TOOLS` 列表导出工具类（非实例），在 `main.py` 中实例化并注册：

```python
# builtins/__init__.py
BUILTIN_TOOLS = [
    ReadFileTool, WriteFileTool, EditFileTool, MultiEditTool,
    BashTool, BackgroundBashTool, LsTool, GlobTool, GrepTool,
]

# main.py
registry.register_many([tool() for tool in BUILTIN_TOOLS])
```

### 关键设计点

- `definition()` 是**方法**而非属性 → 支持动态工具描述变更
- `execute()` 是 `async` 方法 → 适配项目 async 架构
- `context_injection()` → 工具可重写此方法，在每次 LLM 调用前提供实时状态信息（返回 None 表示无需注入）
- `cleanup()` → Agent 退出时统一调用，子类按需重写用于资源清理
- `ToolRegistry.execute()` 内置异常兖底，返回 `is_error=True` 的 `ToolResult`
- `ToolRegistry.collect_context()` 遍历所有工具的 `context_injection()`，拼接为完整上下文字符串
- `ToolRegistry.cleanup_all()` 统一调用所有工具的 `cleanup()` 方法
- `BashTool` 的持久会话在实例级别维护，确保同一实例共享 shell 上下文
- `BackgroundBashTool` 使用类变量维护任务状态，支持动态上下文注入和资源清理

## 四、Agent Loop 核心 + 事件驱动系统

### Agent Loop（`src/agent/agent.py` ~75 行）

- `Agent` 类：管理完整的流式对话 + 工具调用循环
- `run()` 方法接收用户输入，返回 `AsyncGenerator[AgentEvent, None]` 事件流
- `_build_messages()` 构建提交给 LLM 的 messages：将 system prompt 与工具动态上下文拼接为单条 system 消息 + 对话历史
- `_loop()` 内部循环：调用 LLM → 流式输出文本 → 判断工具调用 → 执行工具 → 重复，直到 LLM 不再调用工具

### 事件流模型（`src/agent/events.py`）

5 种事件类型，全部基于 Pydantic BaseModel：

| 事件 | 含义 | 字段 |
|------|------|------|
| `TextDelta` | LLM 流式输出的文本片段 | `content: str` |
| `ToolCallStart` | LLM 决定调用工具（执行前触发） | `tool_name: str`, `arguments: dict` |
| `ToolCallResult` | 工具执行完成的结果 | `tool_name: str`, `result: str` |
| `ResponseComplete` | LLM 最终回复结束 | — |
| `UsageReport` | 单次 LLM 调用的 token 用量 | `prompt_tokens`, `completion_tokens`, `total_tokens` |

### 事件流时序

**有工具调用时：**
```
ToolCallStart → ToolCallResult → UsageReport（第一轮）
TextDelta... → ResponseComplete → UsageReport（第二轮）
```

**无工具调用时：**
```
TextDelta... → ResponseComplete → UsageReport
```

### CLI 入口（`main.py` ~83 行）

- 事件驱动消费模型：`async for event in agent.run(...)` + `isinstance` 分发
- 彩色终端输出：红色=文本、绿色=工具调用/结果、灰色=用量

## 五、BashTool 超时优化与 background_bash 引导（2026-04-03）

### 问题

LLM 经常用 `bash` 工具执行长时间运行的命令（如启动 dev server），导致阻塞等待直到超时，而不是使用 `background_bash`。

### 改动内容（`bash.py`）

1. **超时时间 120s → 30s**：缩短默认超时，减少不必要的等待
2. **强化工具描述中的不适用场景**：

   - 时间阈值从"2 分钟"改为"30 秒"，与实际超时一致
   - 新增兜底提示："如果你不确定命令是否会快速结束，请优先使用 background_bash"
3. **超时错误信息加入引导**：
   - 明确告知命令已被强制终止、shell 会话已重置（环境变量/工作目录等状态丢失）

4. **工具描述补充超时后果**：在执行模式中说明超时会导致 shell 会话重置

## 六、CLI 优雅退出与中文输入修复（2026-04-03）

### 问题

1. **Ctrl+C 需要按两次才能退出**：`asyncio.run()` 安装了自己的 SIGINT 处理器，第一次 Ctrl+C 只设置标志，阻塞的 `input()` 无法被中断
2. **退出时打印两次 Bye!**：内层 `except` 和外层 `except` 各打印一次
3. **退出时出现 traceback**：`run_in_executor` 方案中线程池里的阻塞 `readline` 无法被取消，导致 threading shutdown 报错
4. **中文输入退格删不干净**：`sys.stdin.readline()` 不走 readline 库，终端对多字节 UTF-8 字符的退格按字节删除

### 演进过程

经历了三个方案的迭代：

| 方案 | 实现 | 问题 |
|------|------|------|
| 方案 1：直接 `input()` | 在 async 函数中直接调用 | 需要按两次 Ctrl+C；打印两次 Bye! |
| 方案 2：`run_in_executor` | 线程池执行 `sys.stdin.readline` | 线程无法取消，退出时 threading shutdown 报错 |
| 方案 3：`loop.add_reader` | 注册 stdin fd 到事件循环 | 一次 Ctrl+C 即可退出，但中文退格有问题（`sys.stdin.readline` 不走 readline 库） |

### 最终方案（`main.py`）

回归 `input()` + readline 库 + 自定义 SIGINT 处理：

1. **导入 `readline` 模块**：激活终端行编辑功能，正确处理中文字符的退格和方向键
   ```python
   try:
       import readline  # noqa: F401
   except ImportError:
       pass
   ```

2. **恢复 SIGINT 为 Python 默认行为**：覆盖 asyncio 的 SIGINT 处理器，使第一次 Ctrl+C 就能中断阻塞的 `input()`
   ```python
   loop = asyncio.get_running_loop()
   loop.remove_signal_handler(signal.SIGINT)
   signal.signal(signal.SIGINT, signal.default_int_handler)
   ```

3. **外层 `asyncio.run()` 静默捕获 `KeyboardInterrupt`**：避免重复打印 Bye!

### 最终效果

- ✅ 一次 Ctrl+C 优雅退出，只打印一次 `Bye!`
- ✅ Ctrl+D（EOF）正常退出
- ✅ 中文输入、退格、方向键正常工作
- ✅ 无 traceback、无线程残留
- ✅ 移除了 `async_input` 函数，代码更简洁（~103 行）
