## 二、OpenAI 客户端封装

### 完成内容

`src/client/openai_client.py` — 基于 `AsyncOpenAI` 封装异步 LLM 调用层。

### 数据模型

| 模型 | 用途 |
|------|------|
| `Usage` | Token 用量（`total_tokens` 为计算属性） |
| `ToolCall` | 单个工具调用（id + name + arguments），含 `to_dict()` |
| `Message` | LLM 返回的完整消息，含 `to_message_dict()` / `has_tool_calls` |
| `StreamDelta` | 流式返回的单个增量片段 |
| `StreamResponse` | 异步流式响应包装器，支持 `async for`，结束后通过 `.message` 获取完整消息 |

### 核心方法

| 方法 | 说明 |
|------|------|
| `chat()` | 异步非流式调用，返回 `Message` |
| `stream_chat()` | 异步流式调用，返回 `StreamResponse` |
| `_retry()` | 指数退避自动重试（1s → 2s → 4s，最多 3 次） |

## 三、工具系统

### 基础设施

`src/tools/` — 工具基类、数据模型、注册中心。

| 类 | 文件 | 职责 |
|------|------|------|
| `ToolDefinition` | `base.py` | 工具定义（name + description + parameters JSON Schema） |
| `ToolResult` | `base.py` | 工具执行结果（content + is_error），含 `to_message_dict()` |
| `BaseTool` | `base.py` | 抽象基类 — `definition()` + `async execute()` |
| `ToolRegistry` | `registry.py` | 注册中心 — register / unregister / get_definitions / execute |

### 内置工具（`src/tools/builtins/`）

#### EditFileTool（`edit_file.py` ~70 行）

通过搜索替换模式精准编辑文件。

| 参数 | 必填 | 说明 |
|------|------|------|
| `path` | ✅ | 文件绝对路径 |
| `old_string` | ✅ | 要被替换的原始文本（精确匹配） |
| `new_string` | ✅ | 替换后的新文本 |
| `expected_replacements` | ❌ | 预期替换次数，默认 1 |

- 严格校验 `old_string` 在文件中的匹配次数是否等于 `expected_replacements`
- 匹配次数不符时直接报错，不执行替换
- 文件不存在时返回错误

#### MultiEditTool（`multi_edit.py` ~128 行）

对同一文件按顺序执行多次搜索替换，具有原子性。

| 参数 | 必填 | 说明 |
|------|------|------|
| `path` | ✅ | 文件绝对路径 |
| `edits` | ✅ | 编辑操作数组 |
| `edits[].old_string` | ✅ | 要被替换的原始文本 |
| `edits[].new_string` | ✅ | 替换后的新文本 |
| `edits[].expected_replacements` | ❌ | 预期替换次数，默认 1 |

- **原子性**：所有编辑在内存中依次应用，任一失败则整体不写回
- **创建新文件**：文件不存在时，若首个编辑的 `old_string` 为空则创建文件
- **追加内容**：`old_string` 为空时直接追加 `new_string` 到内容末尾
- 编辑按顺序应用，后续编辑基于前一编辑的结果

#### ReadFileTool（`read_file.py` ~74 行）

读取本地文件内容，支持行范围。

| 参数 | 必填 | 说明 |
|------|------|------|
| `path` | ✅ | 文件绝对路径 |
| `offset` | ❌ | 起始行号（从 1 开始） |
| `limit` | ❌ | 读取行数 |

- 输出 `cat -n` 格式（带行号）
- 单行最长 2000 字符，超出截断
- 默认最多读取 2000 行

#### WriteFileTool（`write_file.py` ~43 行）

创建或覆盖写入文件。

| 参数 | 必填 | 说明 |
|------|------|------|
| `path` | ✅ | 文件绝对路径 |
| `content` | ✅ | 写入内容 |

- 父目录不存在时自动创建
- 返回写入字符数

#### LsTool（`ls.py` ~77 行）

列出给定路径中的文件和目录。

| 参数 | 必填 | 说明 |
|------|------|------|
| `path` | ✅ | 要列出内容的目录绝对路径 |
| `ignore` | ❌ | glob 模式数组，用于忽略匹配的文件/目录 |

- 条目按 **目录在前、文件在后** 排序，同类按名称字母序排列
- 目录显示为 `[目录] name/`，文件显示为 `[文件] name (大小)`
- 文件大小自动格式化为 B / KB / MB / GB / TB
- 使用 `fnmatch` 匹配 ignore 中的 glob 模式
- 路径不存在、不是目录、权限不足时返回错误

#### GlobTool（`glob.py` ~61 行）

快速文件模式匹配工具，适用于任意规模的代码库。

| 参数 | 必填 | 说明 |
|------|------|------|
| `pattern` | ✅ | glob 模式，例如 `**/*.py` 或 `src/**/*.ts` |
| `path` | ✅ | 搜索的起始目录绝对路径 |

- 使用 `Path.glob()` 进行模式匹配，只保留文件（过滤目录）
- 结果按修改时间降序排序
- 输出相对于搜索根目录的路径
- 捕获无效 glob 模式的 `ValueError` 异常
- 路径不存在或不是目录时返回错误
- 没有匹配结果时返回友好提示

#### GrepTool（`grep.py` ~87 行）

快速内容搜索工具，在文件中搜索匹配正则表达式的行。

| 参数 | 必填 | 说明 |
|------|------|------|
| `pattern` | ✅ | 正则表达式模式（Python re 语法），例如 `def\s+main`、`import.*os` |
| `path` | ✅ | 搜索的起始目录绝对路径，会递归搜索所有子目录 |
| `include` | ❌ | 按文件名模式过滤，例如 `*.py`、`*.{js,ts}`。不指定则搜索所有文件 |

- 输出格式为 `文件路径:行号:匹配内容`
- 使用 `Path.rglob()` 递归遍历文件，结合 `re` 模块逐行匹配
- 文件按修改时间降序排序
- 最多返回 200 条结果（`MAX_RESULTS`），超出时截断并提示
- 捕获无效正则表达式的 `re.error` 异常
- 路径不存在或不是目录时返回错误
- 没有匹配结果时返回友好提示

#### BashTool（`bash.py` ~94 行）

在持久 shell 会话中执行命令。

| 参数 | 必填 | 说明 |
|------|------|------|
| `command` | ✅ | 要执行的 shell 命令 |
| `timeout` | ❌ | 超时秒数，默认 120，最大 600 |

- **持久会话**：通过类变量 `_process` 维护同一个 `/bin/bash` 子进程，上下文（环境变量、历史等）跨调用共享
- **sentinel 机制**：用随机标记 + `$?` 获取退出码，精确区分命令输出边界
- 输出超过 30000 字符时截断（保留首尾）
- 超时后自动 kill 进程并重置会话

### 工具注册

`BUILTIN_TOOLS` 列表导出工具类（非实例），在 `main.py` 中实例化并注册：

```python
# builtins/__init__.py
BUILTIN_TOOLS = [ReadFileTool, WriteFileTool, EditFileTool, MultiEditTool, BashTool, LsTool, GlobTool, GrepTool]

# main.py
registry.register_many([tool() for tool in BUILTIN_TOOLS])
```

### 关键设计点

- `definition()` 是**方法**而非属性 → 支持动态工具描述变更
- `execute()` 是 `async` 方法 → 适配项目 async 架构
- `ToolRegistry.execute()` 内置异常兜底，返回 `is_error=True` 的 `ToolResult`
- `BashTool` 的持久会话在实例级别维护，确保同一实例共享 shell 上下文

## 四、Agent Loop 核心 + 事件驱动系统

### Agent Loop（`src/agent/agent.py` ~62 行）

- `Agent` 类：管理完整的流式对话 + 工具调用循环
- `run()` 方法接收用户输入，返回 `AsyncGenerator[AgentEvent, None]` 事件流
- `_loop()` 内部循环：调用 LLM → 流式输出文本 → 判断工具调用 → 执行工具 → 重复，直到 LLM 不再调用工具

### 事件流模型（`src/agent/events.py`）

5 种事件类型，全部基于 Pydantic BaseModel：

| 事件 | 含义 | 字段 |
|------|------|------|
| `TextDelta` | LLM 流式输出的文本片段 | `content: str` |
| `ToolCallStart` | LLM 决定调用工具（执行前触发） | `tool_name: str`, `arguments: dict` |
| `ToolCallResult` | 工具执行完成的结果 | `tool_name: str`, `result: str` |
| `ResponseComplete` | LLM 最终回复结束 | — |
| `UsageReport` | 单次 LLM 调用的 token 用量 | `prompt_tokens`, `completion_tokens`, `total_tokens` |

### 事件流时序

**有工具调用时：**
```
ToolCallStart → ToolCallResult → UsageReport（第一轮）
TextDelta... → ResponseComplete → UsageReport（第二轮）
```

**无工具调用时：**
```
TextDelta... → ResponseComplete → UsageReport
```

### CLI 入口（`main.py` ~52 行）

- 事件驱动消费模型：`async for event in agent.run(...)` + `isinstance` 分发
- 彩色终端输出：红色=文本、绿色=工具调用/结果、灰色=用量
